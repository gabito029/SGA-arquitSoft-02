# Decisiones arquitectónicas

| ID | Decisión arquitectónica | Driver relacionado | Justificación | Resultado |
|---|---|---|---|---|
| ADR-001 | **Monolito modular** | DA05 – Desarrollo individual | Organizar las funcionalidades en módulos independientes dentro de una sola aplicación desplegable, que una persona puede construir, probar y desplegar. | Módulos de Identidad, Catálogo, Requerimientos, Reglas, Firma, Inventario, Auditoría y Reportes. |
| ADR-002 | **Clean Architecture dentro de cada módulo** | DA05 – Desarrollo individual; AC07 – Mantenibilidad | Separar las reglas del negocio (conducto regular, firma digital e inventario) de los detalles tecnológicos (FastAPI, PostgreSQL, librería de firma y almacenamiento de PDF), para probarlas sin base de datos y cambiar la tecnología sin modificarlas. | Capas de Dominio, Aplicación, Infraestructura y Presentación en cada módulo. | 
| ADR-003 | **Una transacción por cada operación que modifica el stock** | DA02 – Consistencia del inventario | Guardar el cambio de estado, los movimientos y la auditoría juntos, y bloquear el stock mientras se actualiza: todo o nada. | Salidas, despachos y recepciones sin efectos a medias. |
| ADR-004 | **Firma digital con clave del sistema en cada nivel** | DA01 – Integridad; DA04 – Conducto regular | Reemplazar las firmas físicas de cada nivel por firmas verificables, sin el costo ni el trámite de certificados acreditados. | Huella SHA-256 y firma Ed25519 para el visto bueno, la conformidad, la autorización, la aprobación y el acta de recepción, con PDF verificable. |
| ADR-005 | **Auditoría encadenada** | DA01 – Integridad; DA06 – Trazabilidad | Cada registro guarda la huella del anterior; si alguien modifica uno, la cadena se rompe. | Verificación de la integridad de la auditoría por el auditor. |
| ADR-006 | **Autenticación con JWT y control por rol y órgano** | DA03 – Seguridad; DA09 – Escalabilidad | Comprobar en cada petición quién es el usuario, qué rol tiene y a qué órgano pertenece, sin guardar sesiones en el servidor. | Ocho roles, desde el oficial de logística de la unidad hasta el auditor y el administrador. |
| ADR-007 | **Flujo de firmas por niveles con máquina de estados** | DA04 – Conducto regular | Cada nivel del conducto regular es un estado; un requerimiento solo avanza cuando el nivel actual firma. | Ningún nivel puede omitirse y cada uno firma una sola vez. |
| ADR-008 | **Reglas de aprobación fijas en la configuración** | DA04 – Conducto regular; DA05 – Desarrollo individual | Las reglas que deciden cuándo interviene el COLOGE (material de guerra o monto alto) se definen en la configuración del sistema. | Reglas simples y comprobables con pruebas automáticas. |
| ADR-009 | **Estructura orgánica registrada como datos jerárquicos** | DA03 – Seguridad; DA04 – Conducto regular | Registrar los órganos con su relación de dependencia permite saber a qué gran unidad pertenece cada unidad y quién debe firmar en cada nivel. | Órganos, unidades y almacenes con relación padre-hijo en el módulo Catálogo. |
| ADR-010 | **Almacenamiento de documentos mediante una interfaz** | DA07 – Bajo costo | Guardar los PDF en el disco local, con la opción de cambiar a otro almacenamiento sin modificar las reglas del negocio. | Implementaciones intercambiables de almacenamiento de documentos. |
| ADR-011 | **Tecnologías de código abierto** | DA07 – Bajo costo; DA08 – Aplicación web y API REST | Usar herramientas gratuitas y adecuadas para construir una API REST y una interfaz web responsiva. | Python con FastAPI, PostgreSQL, React con TypeScript y Docker Compose. |
| ADR-012 | **API sin estado con balanceo de carga** | DA09 – Escalabilidad | Como la sesión viaja en el token JWT, se pueden levantar varias instancias de la API y repartir las peticiones entre ellas. | Nginx reparte las peticiones entre las instancias de la API levantadas con Docker Compose. |
| ADR-013 | **Monitoreo de estado y reinicio automático** | DA09 – Disponibilidad | Detectar cuándo la aplicación deja de responder y reiniciarla sin intervención manual. | Punto de verificación de estado (`/health`) y reinicio automático de contenedores con Docker Compose. |
